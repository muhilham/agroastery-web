# Next.js Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade `next` from 15.1.2 to 16.2.3 to resolve 2 critical CVEs and 21 additional vulnerabilities.

**Architecture:** Pure dependency bump — update `package.json`, resolve the lockfile, verify the build and lint pass. No application code changes are expected.

**Tech Stack:** Next.js 16.2.3, pnpm, ESLint with eslint-config-next

---

## File Structure

| File | Change |
|---|---|
| `package.json` | Bump `next`, `eslint-config-next`, `@next/eslint-plugin-next`; remove `@vercel/og` |
| `pnpm-lock.yaml` | Auto-regenerated by `pnpm install` |

No other files should need to change. If `pnpm build` surfaces TypeScript or config errors, they indicate a pre-existing issue to fix inline.

---

### Task 4: Verify build

- [ ] **Step 1: Run the production build**

```bash
pnpm build
```

Expected: build completes successfully with no errors.

If the build fails with a TypeScript error referencing a Next.js type (e.g., `PageProps`, `Metadata`), check the Next.js 16 migration guide for the affected type and update it. The most common change is `params` and `searchParams` in page components becoming `Promise<...>` — if this surfaces, update the affected page to `await params` before use.

If the build fails with an unknown config key in `next.config.ts`, remove or rename that key per the error message.

- [ ] **Step 2: Run pnpm audit to confirm CVEs are resolved**

```bash
pnpm audit
```

Expected: 0 vulnerabilities found (or only vulnerabilities unrelated to `next`).

---

### Task 5: Verify lint

- [ ] **Step 1: Run ESLint**

```bash
pnpm lint
```

Expected: no errors. Warnings are acceptable.

If new lint errors appear, they are likely from updated `eslint-config-next` rules. Fix them before committing.
